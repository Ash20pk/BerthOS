# Gap analysis: `@berth/agents` vs. LangChain/LangGraph

Working list of concrete gaps found by auditing `packages/agents`, `packages/mesh-coordinator`/`mesh-daemon`, `packages/sdk`, and `packages/sdk-python` against LangChain/LangGraph's feature set (2026-08-04). Ranked by how quickly each would surface in a head-to-head technical evaluation. Status is updated as gaps get closed — see the progress log at the bottom for what changed and why.

Design constraint that shapes every "fixed" entry below: **no LangGraph-style node/edge graph DSL.** Where LangGraph would reach for a dedicated subsystem (a checkpointer, an interrupt primitive, a tracer), Berth's answer is to expose primitives the OS layer already has (Semantic FS, Context Bus, grants-server) to `@berth/agents`, rather than build a parallel one.

## Status key

- 🔴 Open — not started
- 🟡 Partial — some real progress, real scope left
- 🟢 Closed — done, verified (tests/build passing)

## Tier 1 — would lose a head-to-head immediately

| # | Gap | Status | Notes |
|---|-----|--------|-------|
| 1 | No state-graph/node-edge orchestration model | 🟢 Closed | **Closed for cycles/fan-out/branching (2026-08-04), branch `feat/crew-composable-functions`**: `Crew` gained `parallel`/`loopUntil`/`route` — same "just wiring over `Agent`" stance as the original three, not a graph DSL. `parallel(agents, {merge?})` fans out to every agent concurrently and combines outputs; `loopUntil({agent, until, maxIterations?})` is the cycle, feeding an agent's own output back in until a predicate fires or a turn cap is hit; `route({router, routes, fallback?})` is the conditional branch, an LLM classifying input to one of a fixed set of downstream agents. **Closed for typed shared state (2026-08-05), branch `feat/crew-pipeline-state`**: `Crew.pipeline<S>(steps)` threads a typed state object across steps instead of only a `string` — the one piece of this gap left after the 2026-08-04 work. See the progress log for details. |
| 2 | Tool-call errors kill the entire agent run | 🟢 Closed | **Closed (2026-08-04), branch `fix/agent-tool-error-handling`**: `Agent.run()`'s tool loop (`agent.ts`) now wraps `tool.invoke()` in try/catch and feeds `{ error: <message> }` back to the model as that call's tool result — same pattern the existing "no such tool" case already used. The model gets a chance to retry, try another tool, or explain the failure, instead of the run throwing straight out. |
| 3 | No token-level streaming | 🟢 Closed | **Closed (2026-08-04), branch `feat/llm-token-streaming`**: `LLMProvider` gained an optional `chatStream(params, onText)`, implemented for real by both built-in providers (`client.messages.stream()` for Anthropic, `stream: true` chat completions for OpenAI, accumulating fragmented tool-call deltas by index). `Agent.run()`/`resume()`/`runAgent()` take an `onText` callback and use `chatStream` when both it and the callback are present, falling back to plain `chat()` otherwise — a custom `LLMProvider` without `chatStream` still works, just without incremental events. |
| 4 | No cross-run memory / checkpointing / durable execution | 🟢 Closed | **Closed for a single `Agent`** (2026-08-04, branch `feat/agent-checkpointing`): `Agent.run(input, {runId})`/`Agent.resume(runId)` + `CheckpointStore` seam (`packages/agents/src/checkpoint.ts`), backed by a real `createSemanticFsCheckpointStore()` that persists after every turn through a resident app's `write_context_file`/`read_context_file`/`tag_context_file` exports. A crash mid-loop no longer loses everything — `resume()` picks the loop back up from the last saved turn. **Closed for `Crew`-level composition state (2026-08-05), branch `feat/crew-checkpointing`**: `CheckpointStore<T>` generalized (was hardcoded to `Agent`'s own `CheckpointedRun`) so `Crew.sequential`/`loopUntil`/`pipeline` reuse the exact same seam and backend for a new `CrewCheckpoint<S>` shape — see the progress log. Still true, by design, not a gap: this doesn't fix gap #2 — a checkpoint preserves the steps/turns *before* a crash, not the crashing one itself. |
| 5 | Zero observability/tracing | 🟢 Closed | **Closed for a single `Agent`'s turns/tool-calls (2026-08-04), branch `feat/agent-tracing`**: `StepTracer` seam (`packages/agents/src/tracing.ts`) + `AgentStepEvent` (`runId, agentName, turn, kind: "llm-turn"|"tool-call", toolName?, durationMs, error?`), emitted after every LLM turn and every tool call when both `trace` and `runId` are set. `createContextBusStepTracer()` publishes to Context Bus topic `agent.step` for live tailing; `createSemanticFsStepTracer()` writes to `/context/agent-traces/<runId>.json` for durable replay (`readAgentTrace()` reads it back); `createAgentTracer()` (`trace: "full"`) does both. **Closed for the remaining three pieces (2026-08-05), branch `feat/agent-tracing-completeness`**: `LLMTurn.usage`/`AgentStepEvent.usage` (`{inputTokens, outputTokens}`), populated by both built-in providers whenever the underlying API reports it; `Crew.sequential`/`parallel`/`loopUntil`/`route`/`withManager`/`networked` now accept a `runId` threaded into every step's `Agent.run()` call so a whole composition's steps correlate under one trace, and `Crew.pipeline` passes it as each step function's second argument (it never calls an Agent itself); `listAgentTraces(computer, {limit?})` finds every traced runId via one `query_context` call (a fixed marker tagged onto every trace file), no runId needed up front. See the progress log for the collision-avoidance detail this interacted with in gap #4's checkpoint key. |

## Tier 2 — credibility gaps once someone reads the code

| # | Gap | Status | Notes |
|---|-----|--------|-------|
| 6 | Multi-agent orchestration (the headline feature) has no unit tests and isn't in CI | 🟢 Closed | **Closed (2026-08-04), branch `test/crew-composition-coverage`**: `crew.test.ts` now covers all six `Crew` shapes — `sequential`, `withManager`, and `networked` joined the already-tested `parallel`/`loopUntil`/`route` — with fake `LLMProvider`s/`Tool`s/a fake `NetworkedAgent`, no Docker/API key needed, and `pnpm test` (hence `crew.test.ts`) already runs on every push/PR via `build-lint-test.yml`. **Still separate, not this gap**: `crew-manager-milestone.mjs`/`crew-networked-milestone.mjs` (real Docker + live `ANTHROPIC_API_KEY` end-to-end runs) stay manual/local-only, same posture as every other credential-gated milestone script in this repo — that's a different concern (real-LLM/real-Docker integration coverage) from "the composition logic itself has no unit tests," which is what this gap named. |
| 7 | No LLM-call retry/backoff, no fallback models | 🟢 Closed | **Closed (2026-08-04), branch `feat/llm-retry-fallback`**: per-call retry already existed but was invisible/unconfigurable — `createAnthropicProvider()`/`createOpenAIProvider()` are thin adapters over `@anthropic-ai/sdk`/`openai`, and both SDK clients already retry 429/5xx/timeouts with their own backoff (`maxRetries: 2` default); both providers now expose `maxRetries` directly. The actual missing piece, a primary/secondary model chain, is new: `createFallbackProvider(providers, {onFallback?})` wraps an ordered `LLMProvider[]` into one — `chat()`/`chatStream()` try each in order, falling through to the next on any thrown error, propagating the last one's error unchanged if all fail. Works with any `LLMProvider` (built-in or custom); `Agent`/`createAgent` need no awareness of it — `llm` just accepts the wrapped provider like any other. |
| 8 | No human-in-the-loop at the agent-loop level | 🟢 Closed | **Closed (2026-08-04), branch `feat/agent-human-approval`**: `applyHumanApprovalGate(tools, options)` (`packages/agents/src/approval.ts`) generalizes `@berth/grants-server`'s existing request/approve/deny/webhook machinery from "container gets this filesystem capability" (async, takes effect on next boot) to "this agent gets to take its next action" (live, blocking). A gated tool call `POST /grants`s (`capability: "agent-action:<toolName>"`, tool input as `reason`), then polls `GET /grants/:id` until a human decides via `berth grants approve/deny` or `timeoutMs` (default 10min) elapses — fail-**closed**, the opposite of the governance gate's fail-open. Denied/timed-out both throw `HumanApprovalDeniedError`, caught generically by `Agent.run()`'s existing tool-error handling (gap #2) — no `Agent` loop changes needed. `only: string[]` scopes which tool names are gated (omit to gate everything). `createAgent({humanApproval})` wires it in without touching `Computer`. Doesn't touch `generate-capability-policy.ts`/Landlock — orthogonal, boot-time-only machinery, and there's no container to restart mid-`Agent.run()` anyway. |
| 9 | RAG/retrieval not surfaced to the agent framework | 🟡 Partial | **Closed for Semantic FS as a retriever (2026-08-04), branch `feat/agent-semantic-fs-retriever`**: `createSemanticFsRetriever()` (`packages/agents/src/retrieval.ts`) wraps Semantic FS's `query_context` + `read_context_file` exports into one `retrieve(text, {topK?})` call (query, then fetch content for each hit, dropping stale paths) and exposes it as a single `search_context` `Tool` via `asTool()`; `createAgent({retriever: "semantic-fs"})` wires it in automatically alongside the raw exports. **Closed for chunking + generic ingestion (2026-08-05), branch `feat/retrieval-ingestion`**: `chunkText()` (a plain character-window splitter, paragraph/sentence-boundary-aware, overlapping) + `ingest(computer, source, text, options?)`, which writes each chunk through the same generic `write_context_file`/`tag_context_file` resolution checkpointing already uses — works with any app exposing that contract. **Still open**: no vector-DB integration (Pinecone/Weaviate/pgvector/etc.) — `Retriever` stays a plain interface specifically so one could be added later, but none exists yet. |
| 10 | No structured-output enforcement/repair loop | 🟢 Closed | **Closed for an `Agent`'s final answer (2026-08-04), branch `feat/agent-structured-output`**: `Agent.run(input, {responseSchema, maxRepairAttempts?})`/`Agent.resume()` parse the model's final (no-tool-calls) turn as JSON and validate it against a Zod `responseSchema`; a parse or validation failure is fed back as a fresh user turn (with per-field Zod issues) for the model to correct, up to `maxRepairAttempts` (default 2), before throwing `StructuredOutputError`. **Closed for the remaining two pieces (2026-08-05), branch `feat/structured-output-completeness`**: a tool-call input failure's raw `ZodError` JSON-array message is now reformatted into the same compact per-field shape (`formatToolInputError()`, detected generically by message *shape*, not `instanceof`, so it works across the RPC boundary for any resident-app export too — real JSON-Schema pre-validation before `invoke()` is still deliberately out of scope, needing a validator dependency this package doesn't have); `Crew.sequential`/`Crew.route` now accept `responseSchema`/`maxRepairAttempts`, reusing `Agent.run()`'s exact repair mechanics on whichever Agent actually produced the composed output (the last agent, or the chosen branch) rather than a second implementation. See the progress log for why `parallel`/`withManager`/`networked`/`loopUntil`/`pipeline` don't get this. |

## Structural (architectural tradeoff, not a code fix)

| # | Gap | Status | Notes |

| 14 | Docker/sandbox cold-start is a real adoption-friction cost | 🔴 Open (by design) | Every gap above assumes a booted sandbox container. ## Tier 4 — broader ecosystem gaps (found via a wider competitive check, 2026-08-05)

Gaps 1-14 above came from a `@berth/agents` vs. LangChain/LangGraph-specific audit. A later, broader pass — CrewAI, AutoGen/Microsoft Agent Framework, OpenAI's Agents SDK, LlamaIndex, Vercel AI SDK, Google ADK, Semantic Kernel — surfaced real gaps that scoping hid, mostly around *interop and distribution* rather than orchestration mechanics (where gaps 1-13's closure already holds up). See the progress log for the full reasoning behind each pick.
