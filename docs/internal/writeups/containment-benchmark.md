## The hook

Every agent-sandbox vendor publishes a comparison where they win. So here is
ours — with the row we lose in it, the positive control that would fail the
run if sabotaging our own sandbox changed nothing, and the rule that a test we
couldn't measure never counts in our favour.

## The shape of the piece

1. **The premise nobody benchmarks.** Not "is it secure" but: *the attacker
   already has code execution inside your sandbox — now what?* That is the
   realistic state after a prompt injection lands. Most sandbox comparisons
   measure startup time.

2. **One probe, not one per target.** The credibility trick is boring and
   structural: `bench/probe/probe.mjs` is the only place an attack is written
   down, and every harness runs that file unmodified. Show the Berth wrinkle —
   it has to run *inside the app's own restricted process*, because Landlock
   binds a process and its children, so probing by `docker exec` would report
   escapes no agent could actually perform. A benchmark that got this wrong
   would flatter us in one direction and libel Docker in the other.

3. **The numbers**, from the generated table: plain Docker 2 of 11 measured
   rows contained; Berth 12 of 13; Berth with its kernel tier switched off,
   8 of 12. Show the table; note it is generated and regenerable.

4. **Why we score 92% and not 100%.** The first full run scored Berth 100%,
   which is exactly the result that should make a reader stop trusting a
   benchmark. So the `docker exec` row went in: anyone holding the host's
   container socket runs a process no in-sandbox policy binds. Red for Docker,
   red for Berth, red for weakened Berth. It is the boundary's edge, and our
   threat model already said so in prose — now it says so in a cell.

5. **The positive control, and what it exposed about ourselves.** Weakening
   Berth drops it 12 → 8, and the runner *fails* if it doesn't. More
   interesting: three rows stayed green with Landlock off, because per-app
   uids and ordinary file permissions were carrying them — not the LSM. A
   green cell means the action was refused, not that Landlock refused it. We
   only know which is which because each cell records the errno and the
   failing syscall. This is the section that shows the benchmark is being used
   on ourselves, not just on the competition.

6. **What we won't claim.** E2B's column reads NOT RUN — the adapter exists,
   an account is a human gate, and a mocked third-party column would poison
   the whole table. Row selection is ours and we ship one of the columns; the
   invitation is to send rows we're missing.
